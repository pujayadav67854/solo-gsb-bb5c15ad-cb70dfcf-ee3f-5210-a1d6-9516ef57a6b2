# 铁路站场进路联锁推演台

小型铁路站场培训用的 Web 进路联锁推演系统：管理员在浏览器中绘制站场（轨道区段、道岔连接、信号机）并定义起终点进路；值班员选择进路、确认道岔位置后申请开放，页面实时显示**能否开放、阻断原因、信号状态与区段占用图**。全部数据保存在本地 SQLite 文件中，刷新页面或重启服务后状态完整恢复。

## 功能与联锁规则

- **进路开放（原子锁定）**：开放检查与加锁在同一个 SQLite 事务中完成。任一条件不满足则整体回滚，**不会留下部分锁定**：
  - 沿途区段必须空闲（从未上报过占用状态的区段按“状态未知 = 占用”处理并在阻断原因中点名）；
  - 道岔实际位置必须与进路要求逐一相符，不符时指出具体道岔及要求/实际位置；
  - 所需区段、道岔不得与任何已开放进路争用，冲突时指出资源及持有进路。
  - 数据库层面对“未释放资源锁”建有条件唯一索引兜底，**两名值班员同时申请冲突进路时保证只有一条成功**。
- **占用/清空事件（按区段递增序号）**：
  - 每个区段独立维护从 1 开始的序号；
  - **同号同内容重传幂等**，不重复生效；**同号异内容、跳号一律拒绝**，错误信息给出涉及区段、期望序号与收到序号；
  - 列车进入首段后起点信号**自动回红**；
  - 已清空且列车已实际到达的经过区段可**自首段起逐段解锁**（列车尚未到达的区段不解锁；前方区段未清空时暂停推进）；
  - 道岔锁在整条进路解除前始终保持；
  - **末段未清空（或状态未知）前不得解除整条进路**；列车尚未进入时可直接取消进路。
- **管理员绘图**：区段 / 道岔（定位、反位各连接两个区段）/ 信号机 / 进路的增删改，图上可拖拽布置；进路保存时做拓扑校验（信号机与首末段一致、相邻区段经指定位置道岔连通、道岔要求必须实际参与衔接）。
- **刷新恢复**：占用状态、事件序号、已开放进路、逐段解锁情况、信号显示全部由数据库重建。
- 内置一个示例站场（1G/2G/3G/4G/5G、SW1/SW2、X1–X4、R1–R3 三条互相冲突的进路），开箱即可演练。

## 技术栈

- Node.js（≥ 20）+ Express
- SQLite（better-sqlite3，同步事务）
- 原生 HTML / SVG / JavaScript 单页，无需前端构建
- Docker / Docker Compose 一键启动，命名卷持久化数据库

## 配置（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 监听端口 |
| `DB_PATH` | 本地 `./data/interlocking.db`；Docker 内为 `/data/interlocking.db` | SQLite 数据库文件路径 |
| `ADMIN_TOKEN` | 空（不启用） | 管理员口令；设置后管理员页的所有写操作（含“复位运行时”）需要该口令，值班员操作不受影响 |

## 启动方式

### 方式一：Docker Compose（推荐，一键完成依赖安装与数据初始化）

```bash
docker compose up -d --build
```

启动后：

- 自动安装依赖、初始化数据库并写入示例站场；
- 数据库保存在 Docker 命名卷 `interlocking-data`（容器内 `/data`），容器重建数据不丢；
- 查看日志：`docker compose logs -f`；停止：`docker compose down`（数据卷保留）。

如需修改端口或设置管理员口令，编辑 `docker-compose.yml` 中的 `ports` 与 `ADMIN_TOKEN`。

### 方式二：本地 Node 运行

```bash
npm install
npm start
```

数据库默认创建在 `./data/interlocking.db`。可用环境变量覆盖，例如：

```bash
PORT=8080 ADMIN_TOKEN=mypass DB_PATH=/opt/il/data.db npm start
```

## 访问地址

启动后用浏览器打开：

> **http://localhost:3000**

（映射端口非 3000 时换成对应端口。）

页面顶部切换两个视图：

- **值班员**：选择进路 → 确认各道岔定位/反位 → “申请开放进路”；在下方按区段提交带序号的占用/清空事件、查看信号与进路锁闭情况、逐段解锁后解除进路。可在右上角填写值班员姓名；两名值班员可分别用两个浏览器/窗口同时操作以演练冲突。
- **管理员**：点击“+ 区段/道岔/信号机/进路”新增，点击图上的图元编辑或删除，管理员模式下可直接拖拽图元调整坐标。“复位运行时”清空全部占用事件与锁闭（站场定义保留），方便重新开课。

## 主要 HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 全站状态（区段占用/序号、锁、信号、活动进路、最近事件） |
| POST | `/api/routes/:id/open` | 申请开放进路，body：`{positions:{SW1:"normal"}, operator:"甲"}` |
| POST | `/api/events` | 提交事件，body：`{section_id, seq, value}`，value 为 `occupy`/`clear` |
| POST | `/api/active/:activeId/release` | 取消（未进入）或解除（末段清空后）进路 |
| POST/DELETE | `/api/admin/...` | 区段、道岔、道岔连接、信号机、进路的维护；`POST /api/admin/reset-runtime` 复位运行时（设置 `ADMIN_TOKEN` 后需带 `x-admin-token` 头） |

错误响应统一为 `{error, message, details}`，`details.reasons` 中逐条列出阻断原因及涉及的区段/道岔。

## 自动化验证

仓库自带端到端场景脚本（需先启动服务）：

```bash
DB_PATH=/tmp/il-test/test.db PORT=3999 node server.js &
node test/e2e.js
```

覆盖：未知状态拒绝、序号幂等/冲突/跳号、道岔位置不符、原子开放、冲突与并发争用只成一条、信号回红、逐段解锁边界、末段未清空禁止解除、重启恢复、管理员拓扑校验等 40+ 断言。
